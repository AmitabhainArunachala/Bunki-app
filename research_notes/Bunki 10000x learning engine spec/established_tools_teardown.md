## Key Question 1: How does JPDB model known vocabulary, media difficulty, i+1 selection, and what is its SRS vs FSRS?

### Takeaway
jpdb keeps a per-word state machine (new / learning / known / due / failed / locked / suspended / never-forget / blacklisted / redundant) over a parsed corpus of every supported anime, novel, VN and game, exposes per-deck coverage percentages and an ML "difficulty" rating for every title, and auto-converts vocab cards into i+1 sentence cards drawn from a 130M+ sentence database; its scheduler is a proprietary ML-trained forgetting-curve model that jpdb says beats SM-2, but no public benchmark against FSRS exists and the algorithm is not documented.

### Cited Findings
- jpdb states it uses "a specialized spaced repetition algorithm based on modern machine-learning techniques which handles things like lapses and irregular reviews, providing better performance than the SM-2 algorithm used by most traditional spaced repetition programs" (snippet; not fetched) — [jpdb FAQ](https://jpdb.io/faq)
- jpdb's algorithm "is based on the forgetting curve and scientific research, using a model that attempts to predict the probability of you remembering a piece of information after a certain period of time" (snippet; not fetched) — [jpdb FAQ](https://jpdb.io/faq)
- i+1: "As you learn new vocabulary, jpdb.io automatically converts vocabulary cards into i+1 sentence cards—sentences where you already know all of the words except the word you're currently learning"; the sentence pool is "over 130 million real Japanese sentences" (snippet; not fetched) — [jpdb.io](https://jpdb.io/)
- Media difficulty: "JPDB uses a machine learning model to generate difficulty ratings for everything in their database, including works which were never rated by a human" (snippet; not fetched) — [jpdb FAQ](https://jpdb.io/faq)
- Coverage: users can "hide decks which have reached the configured target coverage", i.e. per-deck coverage percentage vs a user-set target is a first-class UI concept (snippet from a userscript README describing jpdb's own setting) — [Kagu-chan/jpdb.io userscripts](https://github.com/Kagu-chan/jpdb.io)
- Word-state taxonomy exposed through the public API and rendered by the jpd-breader extension: New, Not-in-deck, Learning, Known, Due, Failed, Never-forget, Locked, Suspended, Redundant, Blacklisted; the extension colors any web text by these states and requires the user's jpdb API key "found in account settings" — [max-kamps/jpd-breader](https://github.com/max-kamps/jpd-breader)
- "Never forget" is both a per-word flag and a deck ("Vocabulary I'll never forget"); "blacklisted" words can be set individually or via global settings "Blacklist particles" / "Blacklist katakana loanwords", and live in a special "Blacklisted vocabulary" deck (snippet; not fetched) — [jpdb changelog](https://jpdb.io/changelog)
- Mechanics visible through community userscripts: a review-time button "I know this, will never forget"; an option to "automatically fail new cards" on first reveal "to combat recency bias"; a "Targeted Sentence Card" mode that hides the target word from the sentence; "FORQ" = front-of-review-queue; locked cards can be unlocked; suspended cards unsuspended; special decks "All vocabulary", "Blacklisted", "Never forget" — [Kagu-chan/jpdb.io userscripts](https://github.com/Kagu-chan/jpdb.io)
- jpdb-connect (archived Oct 2024) exposed jpdb to Yomichan/JL via the AnkiConnect protocol on localhost:3030, could "automatically add [vocab] to a specified deck", "automatically unlock and/or add vocab to the front of the review queue (FORQ)", and "mine selected text as custom definition"; it needed a session cookie for auto-add and required plaintext definitions ({selection-text} rather than {glossary}) — [kampffrosch94/jpdb-connect](https://github.com/kampffrosch94/jpdb-connect)
- Third-party ecosystem built on the jpdb API: meikidroid (Android OCR game dictionary "Uses jpdb.io", 35 stars), jpdb-connect-android ("mine selected words to jpdb.io (Text selection or Anki format sharing)"), JpdbGameDecks ("JPDB vocabulary/kanji decks for studying Japanese video game text"), yomu-reader (colors words by known-state from "Anki, Jiten, Bunpro, JPDB, and WaniKani") — [GitHub topic: jpdb](https://github.com/topics/jpdb); [yomu-reader](https://github.com/HRussellZFAC023/yomu-reader)
- jpdb's frequency list and kanji data are distributed as Yomitan dictionaries ("JPDB" frequency, "JPDB Kanji"), so its corpus-derived frequency is a de-facto community standard even outside jpdb — [MarvNC/yomitan-dictionaries](https://github.com/MarvNC/yomitan-dictionaries)
- jpdb has a Patreon page ("creating a Japanese dictionary and an all-in-one learning system") — [Patreon](https://www.patreon.com/jpdb)

### Inferences
- jpdb's "known" model is deck-agnostic and corpus-wide: because every title is pre-parsed, coverage = (tokens in title whose word-state is known or never-forget) / total tokens, which is why the same state changes instantly update coverage on every deck. A competing product needs the same three primitives: (1) a global per-lemma state, (2) a pre-tokenised corpus of media, (3) a target-coverage concept per title.
- The "redundant" and "locked" states imply jpdb suppresses a card whose learning is implied by another (e.g. a kanji already covered, or a word gated behind prerequisites); this is prerequisite-aware scheduling that Anki lacks.
- jpdb's scheduler is closed-source and single-user-fit is not user-controllable (no parameter optimisation UI documented), so FSRS-6/7 in Anki is currently the only benchmarked, user-optimisable scheduler in the Japanese stack. jpdb's edge is not the algorithm but the data model around it (states + corpus + i+1).
- Userscripts that "automatically fail new cards" and "make it harder to never-forget a new card" show jpdb's default flow lets users over-mark words as known, i.e. known-state inflation is a design risk jpdb shares with LingQ.

### Gaps
- jpdb's review grade buttons, exact interval schedule, how "known" is derived from review state (interval threshold?), and how "difficulty" is computed (features used) could not be verified because jpdb.io was blocked and no fetched third-party source described them. A previous sub-question prompt asked whether the grades are Nothing/Something/Hard/Okay/Easy; no fetched source confirmed this, so it is unverified.
- Pricing (free tier vs Patreon perks) and whether a native mobile app exists: not verifiable in this session (only the existence of a Patreon page is confirmed).
- No public head-to-head benchmark of jpdb's scheduler vs FSRS was found; jpdb's "better than SM-2" claim is self-reported.

## Key Question 2: What do WaniKani and Bunpro do that keeps users loyal?

### Takeaway
WaniKani's retention lever is a rigid, gated dependency graph (radicals → kanji → vocab, unlocked at Guru) with a mnemonic story for every item and a fixed 8-step interval ladder; Bunpro's is cloze-style grammar SRS with "ghost" reviews (a second, short-interval SRS for lapsed sentences), cram mode and textbook-ordered paths — but Bunpro's own community documents that its interval/demotion logic frustrates users.

### Cited Findings
WaniKani
- "WaniKani has five SRS stages for each item: Apprentice (4 levels), Guru (2 levels), Master, Enlightened, and Burned. The intervals go something like: 4 hours, 8 hours, 1 day, 2 days, 1 week, 2 weeks, 1 month, 4 months" (snippet of official KB; not fetched) — [WaniKani SRS Stages](https://knowledge.wanikani.com/wanikani/srs-stages/); the exact Apprentice timings are 4h, 8h, 23h, 47h per a third-party explainer (snippet) — [Wanilog: How WaniKani SRS works](https://wanilog.com/guides/wanikani-srs-explained)
- "Radicals are building blocks for learning kanji... When the radicals reach the guru stage, the kanji using these radicals will be unlocked" and "WaniKani has mnemonics to teach you every single radical, kanji, and vocabulary word on the site" (snippet) — [WaniKani](https://www.wanikani.com/); [Wakoku: WaniKani levels explained](https://wakokujp.com/wanikani-levels-explained/)
- Pricing (third-party, 2026): "$9.00 a month, $89.00 a year, or $299.00 once for lifetime access... the first 3 levels are free" — [Wanilog: Is WaniKani worth it in 2026?](https://wanilog.com/guides/is-wanikani-worth-it)
- Ecosystem signal: asbplayer added "WaniKani token source integration" and "Anki/WaniKani stats projections" (v1.18.0), i.e. WaniKani's per-item SRS stage is consumed by third-party readers to color known words — [asbplayer releases](https://github.com/killergerbah/asbplayer/releases)
- WaniKani's official GitHub org hosts WanaKana (942 stars) and notifier apps, but no public API-docs repo; API docs live at docs.api.wanikani.com (blocked here) — [github.com/WaniKani](https://github.com/WaniKani)

Bunpro
- Review model: "SRS smart flashcards, tons of example sentences, audio, cram, textbook paths" (App Store listing snippet) — [Bunpro on App Store](https://apps.apple.com/app/id1615337616)
- Ghost reviews: "Ghost Reviews are reviews that you have gotten incorrect and come back to haunt you (leeches). If you get an item incorrect, that particular sentence will automatically be added to your review queue in addition to your normal reviews... Ghost Reviews utilize a separate SRS" and "Ghost Review intervals are now 4 hours, 12 hours, 24 hours, and 48 hrs, meaning that you will see your Ghost sentence four times over the course of the next four days" (2018 announcement; snippet, not fetched; may have changed since) — [Bunpro Community: Ghost Reviews (Update! - Community complaint thread "Bunpro's bad SRS algorithm is discouraging" (125+ replies): OP "had a study session with ~55% accuracy and was frustrated by how many cards were demoted in SRS level"; recurring themes: "cards frequently jump between beginner and adept levels, getting 'promoted' too quickly in relation to actual retention"; some users prefer "strictness level 2 with ghosts turned off"; also "timing discrepancies... between stored intervals and actual intervals" (snippet; not fetched) — [Bunpro Community thread 90066](https://community.bunpro.jp/t/bunpros-bad-srs-algorithm-is-discouraging/90066)

### Inferences
- The loyalty mechanics are structural rather than algorithmic: WaniKani's dependency gating turns kanji learning into a level-progression game with a visible "Burned" terminal state; Bunpro's ghosts make failure visible and time-boxed (4 exposures over ~4 days). Neither uses a probabilistic memory model; both use fixed ladders.
- Bunpro's "strictness" setting and the demotion complaints indicate that a fixed-ladder SRS with punitive demotion generates review pile-ups; a modern product should replace demotion with a stability-based reschedule (FSRS-style) while keeping the ghost/leech visibility that users like.
- The market treats WaniKani's stage number as an interoperable "known-ness" signal (asbplayer, yomu-reader import it), so any new product should export a per-item mastery level through an API from day one.

### Gaps
- WaniKani's incorrect-answer penalty formula, the "60 levels"/item counts, and the Guru-unlock percentage for level-up were not verifiable (KB blocked). Bunpro's main (non-ghost) interval table, strictness definitions, hint levels, cloze vs "reveal-and-grade" mode details, grammar-point count and pricing were not verifiable (bunpro.jp and its forum blocked). Commonly cited Bunpro pricing (~$5/mo, ~$50/yr, ~$150 lifetime) is from memory and is UNVERIFIED.

## Key Question 3: What does the Yomitan + Anki + asbplayer mining stack do end to end, and what breaks?

### Takeaway
The stack is: Yomitan (popup dictionary over v3 JSON dictionaries incl. monolingual, pitch and frequency banks) → AnkiConnect → a Japanese note type (Lapis) with audio from a local 250k-expression audio server, while asbplayer (or mpvacious/Memento on mpv) supplies subtitle-timed audio and screenshots and, via an AnkiConnect proxy, "updates the last card" for true one-click mining; the pain points are browser/platform fragility (Chromium-only audio, no Safari/iOS Yomitan), streaming-site breakage, subtitle sync, missing/wrong-pitch audio, and note-type complexity with no mobile parity.

## Key Question 5: State of FSRS and Anki scheduling features (2025–2026)

### Takeaway
FSRS-6 (21 parameters, trainable power-law decay) is what Anki 26.09 ships (fsrs-rs 6.6.2); FSRS-7 (34 parameters, designed for fractional/intraday intervals, recency-weighted training, "ADR") was merged into fsrs-rs main in September 2026 and is being aligned with the benchmark but has not appeared in a tagged fsrs-rs release or Anki build as of 2026-09-28. On the 10,000-user, ~350M-review benchmark, FSRS-7 (recency) reaches log-loss 0.3363 vs FSRS-6 0.3460, FSRS-4.5 0.3625, HLR 0.4694, with only large neural models (GRU/LSTM/RWKV) doing better.

### Cited Findings
FSRS model
- FSRS tracks Retrievability ("probability that the person can successfully recall"), Stability ("time, in days, required for R to decrease from 100% to 90%"), Difficulty ("inherent complexity"); reasonable desired retention "between 70% and 97%"; "older FSRS versions considered only the first daily review, while FSRS-6 processes all reviews" — [awesome-fsrs wiki: ABC of FSRS](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/ABC-of-FSRS)
- FSRS-6 has 21 weights (w0–w20); forgetting curve "R(t,S) = (1 + factor · t/S)^(-w20)" with trainable decay w20 and factor chosen so R(S,S)=90%; post-recall stability S'r = S·(e^(w8)·(11−D)·S^(−w9)·(e^(w10·(1−R))−1)·hard/easy multipliers (w15, w16) + 1); post-lapse stability S'f = w11·D^(−w12)·((S+1)^w13 − 1)·e^(w14·(1−R)); same-day S'(S,G) = S·e^(w17·(G−3+w18))·S^(−w19); FSRS-5 had 19 parameters — [awesome-fsrs wiki: The Algorithm](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm)
- FSRS-7: "designed to work with fractional interval lengths"; recency weighting means "older reviews affect the loss function less and newer reviews affect it more"; a "penalties" variant addresses "extremely short intervals for same-day reviews at high (97–99%) desired retention and massive interval length jumps at low desired retention"; "preset" and "deck" variants learn partition-specific parameters; 34 default parameters beginning 0.041, 2.4175, 4.1283, 11.9709, 5.6385, 0.4468, 3.262 — [srs-benchmark README](https://raw.githubusercontent.com/open-spaced-repetition/srs-benchmark/main/README.md)
- fsrs-rs: PR #412 "FSRS-7 ADR support" and #426 "FSRS7 with ADR and optimization" merged Sep 8, 2026; #455 "Default parameters to FSRS-7" and #456 "Exposed FSRS model version" merged Sep 18, 2026; #462/#463 ("Remove FSRS-7 parameter pre-training", "Align FSRS-7 training with srs-benchmark") opened Sep 25, 2026; #426 adds "fractional interval results for same-day reviews" and "Newton-Brent root-finding for interval calculations" — [fsrs-rs issues/PRs mentioning FSRS-7](https://github.com/open-spaced-repetition/fsrs-rs/issues?q=FSRS-7); [PR #426](https://github.com/open-spaced-repetition/fsrs-rs/pull/426)
- Latest tagged fsrs-rs release is v6.6.2 (Aug 28; FSRS-6 series); no FSRS-7 tagged release yet — [fsrs-rs releases](https://github.com/open-spaced-repetition/fsrs-rs/releases); py-fsrs (v6.3.2) and fsrs-optimizer (v6.5.0) are also still FSRS-6/21-parameter — [py-fsrs releases](https://github.com/open-spaced-repetition/py-fsrs/releases); [fsrs-optimizer releases](https://github.com/open-spaced-repetition/fsrs-optimizer/releases)

Benchmark (open-spaced-repetition/srs-benchmark)
- Dataset: 10,000 Anki users, ~727M reviews, 349.9M used for evaluation without same-day reviews (519.3M with); metrics log loss, RMSE(bins), AUC — [srs-benchmark README](https://raw.githubusercontent.com/open-spaced-repetition/srs-benchmark/main/README.md)
- Results (no same-day): RWKV-Instant 0.2773 / 0.0250 / 0.8329 (2.76M params); RWKV-Curve 0.3193; GRU 0.3328 (503 params); LSTM 0.3332 (8,869); FSRS-7 recency (100 epochs) 0.3363 / 0.0576 / 0.7243 (34); FSRS-7 0.3401 / 0.0634 / 0.7167 (34); MOVING-AVG 0.3369; FSRS-6 0.3460 / 0.0653 / 0.7034 (21); FSRS-5 0.3561 / 0.0742 / 0.7010 (19); FSRS-4.5 0.3625 / 0.0764 / 0.6891 (17); DASH variants 0.3681–0.3728; AVG 0.3945 / 0.1034 / 0.4997; HLR (Duolingo) 0.4694 / 0.1275 / 0.6369; Ebisu v2 0.4989 / 0.1627 / 0.6051 — [srs-benchmark README](https://raw.githubusercontent.com/open-spaced-repetition/srs-benchmark/main/README.md); [srs-benchmark repo](https://github.com/open-spaced-repetition/srs-benchmark)
- Caveat stated by the benchmark: "SM-2 wasn't designed to predict probabilities, and the only reason it does that in this benchmark is because extra formulas for converting intervals given by SM-2 into probabilities were added on top of it" — [Expertium benchmark page (snippet; blocked)](https://expertium.github.io/Benchmark.html)
- Third-party summaries (UNVERIFIED against primary): "FSRS-6 (with recency weighting) has a 99.6% superiority over Anki SM-2" and "students using FSRS need 20 to 30 percent fewer reviews to maintain the same retention rate" — [Mindomax: FSRS vs SM-2](https://www.mindomax.com/fsrs-vs-sm2-spaced-repetition-algorithm); [Antiagent: FSRS vs SM-2](https://www.antiagent.io/blog/fsrs-vs-sm-2)

### Inferences
- For a new product, the defensible baseline is FSRS-6 with per-user optimisation, and FSRS-7's design goals (fractional intervals for same-day/intraday learning, recency weighting, penalties at extreme retention) point at exactly the short-interval regime a mobile "study several times a day" app lives in. Implementing FSRS-7 from fsrs-rs main would leapfrog Anki stable.
- The benchmark shows 500-parameter GRU/LSTM models beat FSRS-7 by ~1% log loss and multi-million-parameter RWKV by ~6 points; a cloud product can afford per-user neural schedulers that a local app cannot, but gains over FSRS-7 are modest relative to gains from better card content (i+1, audio, context).
- Anki's remaining user pain (FSRS still opt-in, manual optimisation, parameter confusion, helper add-on features) defines the "zero-config scheduler" opportunity: auto-optimise, auto-load-balance, easy days and "flatten" built in.

## Key Question 8: Other state-of-the-art pieces — Renshuu, Kitsun, Kanji Study, Language Reactor, Jimaku, and the Refold/TheMoeWay/Donkuri "stack" and textbook benchmarks

### Takeaway
Renshuu is the most complete all-in-one (kanji, vocab, grammar, pitch, writing, dozens of question types, adjustable SRS) with a genuinely usable free tier; Kitsun is "Anki flexibility with WaniKani polish" plus a reader; Kanji Study is the reference for stroke-recognition writing practice and graded-reading sets; the immersion guides converge on Kaishi 1.5k → Yomitan/Anki(FSRS)/Lapis → asbplayer/ttsu/mokuro, with Tae Kim/Cure Dolly/IMABI/DoJG as grammar references and textbooks (Genki/Tobira) as the JLPT-ordered alternative.

### Cited Findings
- Renshuu content/mechanics (App Store/Play snippets): "over 15,000 native-recorded audio files for vocabulary, 12,000+ kanji with 2,000 colorful mnemonics, and 800+ grammar expressions"; "SRS-for-Japanese quiz system that disaggregates learning items... mastery schedules and dozens of varied question styles with flexible input options"; practice "can include recognition, listening, writing, pitch accent, and sentence-based questions"; "SRS system is more adjustable than WaniKani's" — [renshuu App Store](https://apps.apple.com/us/app/renshuu-japanese-learning/id1542730063); [Languavibe Renshuu vs WaniKani](https://languavibe.com/renshuu-vs-wanikani/)
- Kitsun: "combines the flexibility of Anki with the convenience of WaniKani"; customise "the way you order your lessons, to customizing the inner SRS intervals to creating your own layouts with HTML and CSS"; "One-click flashcard generation from your video of choice"; "A reading tool that parses any text... see the structure of sentences and definitions with lookup"; community decks (third-party) — [Kitsun.io](https://kitsun.io/); [Tofugu Kitsun entry](https://www.tofugu.com/japanese-learning-resources-database/kitsun/)
- Kanji Study: "SRS, flashcards, multiple choice quizzes, writing challenges, kanji and word search, custom sets"; tap a kanji for "stroke order to its kunyomi... and onyomi readings"; ordering by "Japanese School Grades, JLPT levels, Frequency in media"; KLC graded reading sets are a paid add-on (third-party) — [Google Play](https://play.google.com/store/apps/details?id=com.mindtwisted.kanjistudy); [Tofugu entry](https://www.tofugu.com/japanese-learning-resources-database/japanese-kanji-study/)
- Language Reactor: "Dual subtitles show the original language and translation... you can blur the target language to practice listening first, then hover over any word"; "Phrase Pump" reviews saved words; chatbot; quality "depends on the subtitle source: studio captions from Netflix are excellent, auto-generated YouTube captions are passable but error-prone" (third-party) — [Languavibe Language Reactor review](https://languavibe.com/language-reactor-review/); [TubeVocab review](https://www.tubevocab.com/blog/en/language-reactor-review); a 2024–25 forum comparison of Language Reactor / Migaku / jidoujisho as subs2srs replacements exists (not fetched) — [language-learners.org thread](https://forum.language-learners.org/viewtopic.php?t=20005)
- Jimaku: Japanese-subtitle archive, kitsunekko successor, hourly scrape, AGPL; asbplayer forwards episode detection to the Jimaku API — [Rapptz/jimaku](https://github.com/Rapptz/jimaku); [asbplayer releases](https://github.com/killergerbah/asbplayer/releases)
- Immersion-guide method (Donkuri, MoeWay-adjacent): start with the Kaishi 1.5k deck (optionally a phonetics deck for radicals); grammar via Cure Dolly (to lesson 39), IMABI ("understands Japanese grammar extremely well" but verbose), Tae Kim ("legendary" but confusing on particles), Dictionary of Japanese Grammar later; avoid finishing isolated kanji books (RRTK450 if needed); begin mining after Kaishi; output practice needed — [donkuri guide page](https://raw.githubusercontent.com/donkuri/learn-japanese/main/guide/index.html); media recommendations by difficulty via a spreadsheet and VNDB/JPDB lists — [donkuri recs page](https://raw.githubusercontent.com/donkuri/learn-japanese/main/recs/index.html)
- TheMoeWay mining page (snippet): install Yomitan, Anki + note type, AnkiConnect, configure asbplayer to create cards via AnkiConnect; Yomitan "should be using the same Note Type as asbplayer" — [learnjapanese.moe/mining](https://learnjapanese.moe/mining/); TheMoeWay Yomitan tutorial exists — [learnjapanese.moe/yomichan](https://learnjapanese.moe/yomichan/)
- Textbook ecosystem signal: "Genki Study Resources" (1.1k stars) provides exercises "for practicing what is taught in Genki"; community CSV of Genki 1 (3rd ed.) vocabulary and an Anki generator that "extracts vocabulary audio from official Genki language-learning files" — [GitHub topic: genki](https://github.com/topics/genki)
- Grammar reference as a Yomitan dictionary: "dojg-consolidated" (Dictionary of Japanese Grammar) — [MarvNC/yomitan-dictionaries](https://github.com/MarvNC/yomitan-dictionaries)

### Inferences
- Renshuu's "disaggregated" items (a word tested separately for reading, meaning, listening, pitch, writing) and Kanji Study's stroke-recognition are the two features absent from jpdb/Anki mining that a serious learner still installs a second app for.
- The community's content benchmarks are effectively: Kaishi 1.5k (vocab on-ramp), Tae Kim/Cure Dolly/IMABI (grammar), DoJG (reference), Genki I/II → Tobira (textbook track), NHK2016/アクセント辞典 (pitch), JPDB/BCCWJ/CC100 (frequency). A new engine should be able to map its items onto these so learners can measure coverage of what they already did.

### Gaps
- Renshuu's SRS schedule details, Kitsun's interval defaults and "hibernation" of known words, Kanji Study's SRS specifics, Language Reactor's pricing, Migaku's current feature set and the Refold Japanese page were not fetchable; Genki/Tobira vocabulary and grammar-point counts and Tae Kim's chapter structure were not verified from primary sources.
