**How to run the pipeline for the remaining words** (303 words have no v2 passage yet):

1. Scout: pick a batch (about 20 words) with the same mix as the pilot (topics, kana-only words,
   second senses), from the word table the scout wrote (id, term, reading, POS, group, meaning,
   defJa, existing passage lengths, level). Give the writer each word's sheet and its existing
   passages.
2. Write three or four passages per word to `source/REVIEW_MCD.md` (one 講 always; differ in
   register and, for two-sense words, in sense), each with `register`, `topic`, `tipJa`,
   `grammar`, `sense`, and an English translation with the same number of sentences.
3. Five checks, each a separate judge (naturalness, facts, level, one target, context); a failed
   passage goes back to the writer as a rewrite or is dropped; record the drops by check.
4. Put the accepted passages in `decks/kotoba-mine/source/mcd/<name>-YYYY-MM-DD.json` (keys are
   entry numbers as strings, `original: true`), then `npx prettier --write` it,
   `python3 decks/kotoba-mine/tools/export_mcd.py`, `npx prettier --write
decks/kotoba-mine/source/mcd.json`.
5. `python3 decks/kotoba-mine/tools/build.py` once without `--frozen` (it mints the new ids and
   prints them); check `source/ids.json` gains only additions.
6. Read the furigana of every new card (print each card's ruby segments); add fixes to
   `source/readings.json` with `cards` set to the new ids, and pin a few in
   `tools/kotoba-deck-ruby.fixtures.json`.
7. Add the new passages' content lemmas to `source/gloss_ja.json` (run the deck's tokenizer over
   them, skip deck words; one line of at most 40 characters each); `test_gloss_ja.py` checks it.
8. Rebuild `--frozen` and `--frozen --profile public`, bump sw.js `VERSION`, run the gates above,
   and commit.
