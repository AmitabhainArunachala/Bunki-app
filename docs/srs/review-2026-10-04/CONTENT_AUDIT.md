# Detailed content audit and 73-word manifest

Reviewed commit `d01dda7c2d3b312cae5ff1bec709ecae56e48ec4`, branch `claude/japanese-vocabulary-dbm2xr`, in `the audited checkout`. Read `docs/srs/CODEX_REVIEW_PROMPT.md` in full. This is a read-only review; no production content or code changed.

**Recommendation: do not release the present public MCD/sentence deck artifacts.** There are demonstrated wrong factual/reading hints, visible cloze answers, sense mismatches, and inadequately established redistribution rights. These are fixable. The original/mined distinction and explicit Japanese definitions are useful foundations, and several sampled entries work well, but successful JSON validation does not establish language accuracy or source permission.

The integrated [review](REVIEW.md) and [standard](../STANDARD.md) control severity and method defaults. Content findings remain applicable after the learner reopened MCD preferences; no fixed passage length is required.

## Scope and evidence limits

The accompanying [sampling CSV](evidence/content-sampling.csv) is the explicit sampling manifest: **73 distinct words, all 12 topics, 321 reviewed records (209 MCD passages plus 112 sentence cards)**. It includes word/topic IDs; sentence/passage IDs; all generated card IDs for each passage; exact source file and line; Japanese and English text; meaning and Japanese definition; marked target ruby and individual-character hints; form/mask counts; asserted source metadata; and concerns. `S1` means the first record in `source/mined.json`; `P1` the first in `source/mcd.json`; generated IDs remove any ambiguity. All the selected word's shipped sentence/MCD records were included, so both mined and written examples were examined rather than selecting only attractive originals. See the 73-word appendix below.

I read source/v2 definitions and examples, edited review/MCD batches, exported mined/MCD JSON, generated decks, and the matching/ranking/export/build code. I compared source text, English translation, target readings, ordinary non-target ruby, masking, and character hints; reproduced representative matcher/alignment cases with the existing code; and scanned the entire exported corpus for exact form occurrence and metadata gaps. Root owns full build/test validation. Language judgments here are an informed review, **not certification by a native Japanese editor**. A record marked “no additional critical defect found” means no critical problem identified in this sample, not proof that every nuance, reading, fact, or right was independently verified. The word-level concern column is broader than the per-record language column, and often includes source or factual uncertainty.

Source `site`, `url`, `licence`, and `kind` are assertions until checked against an owner-controlled page. I checked a limited set of owner/license texts and factual primary sources listed below. I did not independently match every mined quote to its upstream work, certify authorship of “Bunki original,” or obtain rights advice. Proposed release gates reflect missing evidence, not a definitive legal conclusion.

## Enforceable style, QA and source rules

1. **Ship reviewed senses, not just terms.** Require entry `sense_id`, POS, learner gloss, concise sense-specific `def_ja`, acceptable forms/lemmas and contextual reading. Every record points to one sense. Related abbreviation, orthography, inflection and different lexeme must be distinguished. English translation must preserve that sense, qualification, dates and factual reference direction. Avoid circular definitions and target phonetic answer leakage (稽’s definition currently names けいこ/こっけい).
2. **Admissibility before score.** Before ranking/export: approved public-use license; exact source span/version; appropriate register/content; standalone reference resolution; coherent context of a useful length; complete target morphology; exactly one answer occurrence across allowed variants; background difficulty reviewed against the learner profile. A score cannot override a failed gate. Sentence-length/punctuation tests only raise review flags, not certify coherence.
3. **Keep mined text exact and contextual.** Persist source paragraph/sentence offsets and hashes, neighboring context for review, and any transformations. For unmodified quotes require exact source equality; for edits label adaptation and require permission. Current whitespace removal/punctuation addition (`rank.py:149–154`) must be recorded, especially for ND inputs. Provide an actual containing article/work/revision URL, not an author directory or empty link.
4. **Do not invent authority in originals.** Default written examples to clearly fictional everyday scenes. Numeric medical, legal, historical, scientific or political assertions require a primary-source claim record, date and editor check; otherwise remove the claim. Avoid unspecified “now,” “recently,” “last election,” “few years ago” in timeless decks. Avoid stale prices, stereotypes and sensational violence/sexual scenes when unrelated to the learning objective. Attribution to a theory must remain attribution, not assertion of established fact.
5. **Audit complete ruby.** Retain token-level reading source and review status; use longest attested proper-name/compound overrides including source parentheses before generic token readings. Flag source-phonetic disagreement, contextual suffix/voicing ambiguity, personal names, split compounds and guessed alignments. Marked target and ordinary surrounding readings both need review. Character cards require explicit verified alignment; omitted characters are acceptable.
6. **Make source permissions machine-readable and rendered.** Record author/translator, source owner, exact URL and revision/access date, original sentence ID, upstream license URL/version, required credit/notice, adaptation permission and release profile. Separate research/private imports from the public deck. Reject empty source URLs or vague “personal study” at public export. Renderer and APKG include per-card credit and license/modified notices; public metadata must not discard `title` (currently `build.py:229–230`). Seek specialist review for unclear grants rather than guess.
7. **Record mining effort and fallback.** A per-word log shows allowed sources searched, queries/variants, candidate counts and rejection reasons; original fallback has a reason and editor. Remove single-kanji exclusion when the objective is a real host-word context. Never require three passages if only one or two safe independent contexts exist. Keep frequency balancing and semantic diversity separate from source eligibility.
8. **Validate actual final artifacts.** Extend final JSON checks to sense/reading review state, exact occurrence across variants, no visible answers/phonetic leakage, coherent passage eligibility, source grants and attribution completeness, translations and character alignments. Check known failure fixtures (率直, きれいなお花, 県ごとに, しがち, 一般の方, 土曜日, 寛仁, 甲賀, 讃岐, repeated 金利). Use human/editor signoff for semantic truth rather than an automated “native quality” badge. Reproducible source manifests and review decisions belong in tracked files, not just `.gitignore`d mining outputs.
