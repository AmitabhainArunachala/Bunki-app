# Bunki / 回廊 KAIRO — research and build package

Date and research cutoff: **2026-09-28 (Asia/Tokyo)**.

Start with **BUNKI_BUILD_SPEC.html** for the navigable A–J engineering specification. **BUNKI_RESEARCH_DOSSIER.html** contains the specification plus all ten research notes, the source index and engineering audit in one offline-readable file. **BUNKI_BUILD_SPEC.md** is the editable source. The ZIP preserves the complete set of deliverables and relative links.

The first milestone is a stateful, tool-using local tutor plus placement and a planner. It includes the evidence/replay seam and minimum teaching-verification gate; subsequent milestones expand the graph, mining, listening/production, efficacy testing and product packaging.

Other files: **SOURCE_INDEX.md** locates cited URLs; **COST_MODEL.json** records exact assumptions and calculated costs; **AUDIT_AND_LIMITATIONS.md** records verification scope and known gaps. **notes/11-design-review.md** is an engineering audit appendix, not an eleventh research track.

Interpretation rules: **PROPOSED/DESIGN** means a design choice, **ESTIMATE/CALCULATED** means arithmetic or planning assumptions, and **UNVERIFIED** means this research could not establish the claim. Vendor descriptions do not prove outcomes. Missing documentation does not prove feature absence. The specification governs when a research note presents multiple alternatives.

The supplied Bunki inventory was not verified against its repository. This package does not implement the application, run its tests, or claim efficacy. It preserves the seven product laws. In particular, live personalized cloud tutoring/ASR/sync cannot be enabled under the current export-file-only rule. Cloud options are researched and costed as conditional alternatives; no law amendment is assumed.
