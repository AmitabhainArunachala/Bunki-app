# Track 10 — Product platform, unit economics, compliance and efficacy

Research cutoff/access date: **2026-09-28**. Source dates are supplied beside URLs; `undated` is explicit. **DESIGN** denotes proposed behavior; **ESTIMATE** denotes arithmetic using declared planning inputs; **UNVERIFIED** denotes missing confirmation. Sources describe capabilities, not verified Bunki implementations. Owner laws are requirements dated 2026-09-28.

## Takeaway

**DESIGN:** Ship a local ledger, deterministic projections, explicit export/import, local retrieval and confirmed proposals first. The literal export-only law blocks automatic personalized API calls, cloud ASR/TTS, analytics, crash payloads and sync. Encryption, consent, BYOK and zero retention do not change the fact of egress. A manually created export file can be processed outside Bunki and a proposal file imported for local confirmation. Live provider gateways and optional sync are conditional future designs requiring an owner-approved law change; they must never become model authority.

**DESIGN:** Prove a narrow learning effect on delayed, held-out tasks under equal study time. Do not claim superiority to every competitor from feature breadth, a usability pilot, or improvements among survivors. A per-skill calibration panel and an inspectable evidence trail are appropriate; a readiness score is prohibited.

**DESIGN:** The durable unit is an event with learner ID, immutable event ID, device ID, device-local sequence, causal parents, evidence time, record time, schema version, asset versions, payload hash, and provenance. A correction appends a superseding event. Export/import deduplicates by event ID plus hash, rejects same-ID/different-payload collisions, verifies references and replays deterministically. Use a pinned reducer/version/configuration declared in the record. Cached projections can be deleted without loss. No transport may send a persisted authoritative learner model because no such model exists.

**DESIGN:** A future multi-device event union needs defined handling of clock skew, identical review attempts, imported backups, concurrent goal edits and device revocation. FSRS-6 must replay one deterministic review order from confirmed grades; merging two “due dates” is not valid. A cloud row marked deleted is not sufficient to remove personal payloads from old immutable replicas.

### Provider gateway, metering and cost

The official Anthropic TypeScript SDK disables browser use by default because client-side API credentials can be exposed. Bunki's current BYOK behavior does not prove it is safe for a distributed product. [Official SDK](https://github.com/anthropics/anthropic-sdk-typescript), undated living documentation, accessed 2026-09-28.

**DESIGN, conditional future gateway:** server-held provider secret; short-lived authenticated app token; per-user/model daily spending limits; idempotency key per logical request; reserve maximum estimated cost before dispatch; reconcile provider usage after completion; enforce timeout/output/tool-call limits; no raw learner text in operational logs; no tool allowing the AI to mutate review state. Meter provider use separately from learner evidence. Retries and verification calls count against the budget. Native secure storage for a user's key is a defense at rest, not a remedy for browser exposure or an egress exemption.

**ESTIMATE — text inference, USD per learner per 30-day month.** Inputs: **6,000** reusable prefix tokens + **1,000** uncached input + **600** output per turn; **30/40/60** turns per day. These are planning assumptions, not measured usage. Sonnet 5 rates retrieved from official pricing: **$2 input / $10 output / $2.50 five-minute cache-write / $0.20 cache-hit per million tokens**. Nightly Haiku batch assumption: **12,000 input + 1,200 output**, at **$0.50/$2.50 per million**, giving **$0.009/day = $0.27/month**. [Official pricing](https://platform.claude.com/docs/en/about-claude/pricing), undated fetched 2026-09-28; see track 05 for cache/retention details and a stale search-snippet discrepancy. All cloud costs here are **conditional** on an authorized external-export workflow or a future law change.

**DESIGN:** Target WCAG 2.2 AA; test real VoiceOver/TalkBack flows, text scaling, keyboard-only use, reduced motion and non-drag alternatives. Mark language spans `ja`/`en`; use semantic ruby with pronunciation available without duplicate screen-reader noise. Do not encode knowledge, uncertainty or pitch solely in color. Supply transcripts/captions and an accessible non-speech route; a modality accommodation must remain visible in evidence provenance. Store interface language, assistive preferences, furigana policy and learner goals as record data. Do not branch the build for John or any other learner.

## Inferences: proposed efficacy protocol

All counts, thresholds and time windows below are **DESIGN/ESTIMATE**, not an assertion that they are validated or sufficient for statistical power. User-requested probe delays are **1, 7 and 30 days**.

1. **Define the claim before the intervention.** Candidate primary claim: adaptive selection improves delayed transfer accuracy on unseen reading-in-context items at equal study minutes versus a fixed-selection Bunki condition. Keep FSRS-6, content quality, total practice opportunity and review-grade authority identical. Separate retention, reading comprehension, listening and production outcomes; never combine them into readiness.
2. **N-of-1 first.** Randomize matched item/concept clusters to adaptive or fixed selection, stratified by initial measured evidence and difficulty. Store assignment, random seed and all exposures locally. Use blocked/interleaved assignment; a simple ABAB whole-app crossover is a poor causal design for irreversible learning and carryover. Interpret results as this learner/these materials, not all learners.
3. **Probes.** Independent, equivalent-form probes at each delay; randomize separate item subsets to delay where feasible so the day1 test does not itself train every day30 item. Keep held-out contexts/sentences/audio from teaching and from AI prompt examples. Record skipped probes, prior hints, access to lookup, modality and elapsed delay. No automatic FSRS update from a research probe; learner confirmation is required to create any review-grade event.
4. **Production and listening.** Human Japanese raters blinded to condition score an analytic rubric separately for task completion, meaning, form, lexical appropriateness and intelligibility. Use new prompts and speakers. Retain audio only locally unless the learner intentionally exports a research package. ASR transcripts and tutor impressions are observed evidence, not measured human ratings. Human scoring agreements and adjudications are reported by dimension.
5. **Calibration.** Before each held-out response, freeze model prediction `p`, node/task/channel IDs, uncertainty interval and reducer version. Report per-domain Brier mean `(p-y)^2`, log loss, calibration plots, sample count and missingness. Compare with a simple base-rate baseline. These are research/diagnostic statistics, never a learner-level readiness number. Use chronological holdouts; no fitting on future evidence.
6. **Small-cohort stage.** An exploratory **24-learner, 8-week** pilot is a recruitment/feasibility estimate, not a powered efficacy claim. Prespecify strata, recruitment, exclusions, attrition, adverse experience, time on task and one primary endpoint. Use participant-level randomization where content contamination is material; otherwise randomize clusters within learners and account for learner/item dependence. Freeze a protocol/version before recruitment.
7. **Statistics.** Report raw counts, condition means, absolute percentage-point differences for binary outcomes and standardized effects only where justified, each with **95% intervals**. Use randomization-based inference for randomized N-of-1 item clusters; hierarchical models or cluster bootstrap for cohort repeated measures. Record all missing outcomes and conduct prespecified sensitivity analyses. No “no difference” claim from a nonsignificant pilot; no selecting only enthusiastic completers.
8. **Power gate.** Estimate variance/intraclass correlation from pilot and simulate power for a preregistered minimum effect. Illustration only: independent equal-sized groups, baseline50%, target10percentage points, normal-approximation constants1.96 and0.84 give `2*(1.96+.84)^2*.25/.10^2 ≈392` observations **per arm**. Repeated observations are not392 independent learners or vice versa; this arithmetic is not Bunki's sample-size plan.
9. **Claim gate.** Release efficacy claims only after the prespecified held-out endpoint clears its planned uncertainty/effect criterion, attrition and protocol deviations are reported, and independent Japanese-language reviewers inspect materials. Publish anonymized aggregate results plus executable analysis; individual ledger exports remain voluntary. A positive owner-only result supports a narrow owner-only statement.

Reporting references: [CONSORT 2025](https://www.bmj.com/content/389/bmj-2024-081123), published **2025-04-14**, supplies a **30-item** randomized-trial checklist; [CENT N-of-1 extension](https://www.bmj.com/content/350/bmj.h1738), **2015-05-14**. Accessed 2026-09-28. They originate in clinical-trial reporting: use their transparency principles as adapted guidance, not a claim that a language app is a medical intervention or that compliance establishes learning effectiveness.
