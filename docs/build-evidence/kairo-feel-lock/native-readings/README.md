```sh
  prototypes/corridor/tools/verify-native-readings.mjs
```

The clean rebuild ignores ambient NINJAL cache state. The first 40 generated
records retain their historical unavailable receipt byte-for-byte; additions
carry an accurate `UnavailableByBuildPolicy` receipt. `first40-baseline.json`
pins ID/order, every lean index row, source text, generated article bytes, and
the shared lookup behaviour those readers can reach. Existing word records,
all first-40 word projections (including intentional absences), semantic
edges, and the capped idiom layer remain PR #69-identical; new vocabulary is
appended without overwriting that compatibility prefix.

The browser receipt hashes its exact source, sidecar, index, manifest,
runtime, standalone, shared layers, all 30 body files, the two requested
reference screenshots, and the four retained comparison captures. Computed
styles are compared with an existing Bunki row, and the captures were visually
inspected against `14-phase1-shelf-v11.png` and
`16-phase1-v11-article.png`: the same card, Mincho reader, ruby, spacing, and
chrome are retained. This is a visual inspection record, not a pixel-diff
claim; content, UI-language state, and device scale differ between captures.

## Publication and device status

All 30 have had two AI editorial passes covering Japanese phrasing, source
boundaries, safety, requested form, and cross-article similarity. That is not
the required human review. Every sidecar record remains
`humanReviewStatus:"pending"`, and `verify-native-readings.py --publication`
therefore fails intentionally. Public publication is blocked until a human
Japanese editor reviews grammar, theology, historical claims, tone, and all
generated ruby.

The automated similarity tripwire compares the 30 authored texts with one
another (longest shared normalized run: 29 characters). It does not certify a
complete V1–V4 transcript-to-article comparison; source-level similarity and
presenter-imitation review remains part of the human publication gate. V5 was
unavailable and must not be represented as audited.

The Chromium verifier is a 390×844 touch-emulation gate, not a real-iPhone
receipt. A cache-busted physical-iPhone N3/N2/N1 walk remains an external gate
and must not be inferred from desktop Chromium emulation.
