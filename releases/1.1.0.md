# Bunki / KAIRO 1.1.0

Planned release date: 2026-10-13 (Asia/Tokyo). Publication is established by the GitHub Release and live build identity.

## Changes

- **Bug reports now reach GitHub.** Until now the bug button saved reports only
  on the phone: the published app has no report service, so nothing was sent
  and nobody saw them. In this release, **Send to GitHub** opens a new issue in
  the Bunki repository with everything filled in. That covers your words and
  what you expected, the app version and screen, the content on screen, the
  language, the viewport and the device's report ID. Tap **Submit new issue**
  there to file it under your GitHub account.
- Reports saved by earlier versions, or saved while the browser blocked the new
  window, show **Send to GitHub** and **Copy report text** in **My reports**.
  A report that was opened on GitHub is marked **Opened on GitHub**.
- Filed reports carry the `kairo-report` label. A scheduled fixer agent checks
  for them every hour, reproduces the problem, and opens a pull request with
  the fix and a test. The pull request runs the full release checks; the fix
  reaches the phone only after it is merged and released.
- Screenshots are attached on GitHub's issue page; the in-app picker is hidden
  while sending to GitHub.

## Data and compatibility

No learner-data, card-ID, backup-format, storage-key or FSRS change. Reports
keep their existing on-device store (`bunki-maintenance-reports-v1`); a saved
report gains only an optional `github_opened_at` time, which 1.0.x ignores.
Learner-data epoch stays 1 with no migration, and rolling back to 1.0.1 is
compatible. The scheduler remains FSRS-6 through ts-fsrs 5.4.1 with
`bunki-fsrs6-r090-defaults-v1`.

Issues are public in this repository. A report contains only what you write
plus the listed screen details; the app reads no other learner data into it.

## Verification

A new release gate, `report-github`, runs the built site without a report
service, as GitHub Pages serves it, with github.com stubbed in Chromium and
WebKit. It checks the following:

- one tap opens the prefilled issue, and the saved report names the same issue;
- long reports are shortened to fit GitHub's address limit while the device
  keeps the full text;
- a blocked window leaves a working **Send to GitHub** link;
- **Copy report text** copies the same issue text (Chromium);
- no console errors are logged.

The app cannot confirm that an issue was actually submitted on GitHub. Opening
GitHub from the home-screen app has not been tested on a physical iPhone. If
GitHub asks you to sign in, sign in once and the prefilled issue stays.
