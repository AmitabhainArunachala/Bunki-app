# Bunki / KAIRO 1.0.2

Planned release date: 2026-10-14 (Asia/Tokyo). Publication is established by the GitHub Release and live build identity.

## Changes

Reduce repeated record validation, copying, hashing and replication work behind the existing screens. Immutable records and views can be reused; storage reads still verify the exact persisted bytes and the current ownership/session rules. Both IndexedDB and SQLite use the same journal replay cache.

Load independent saved-data validators concurrently while keeping record admission and recovery ordered. Coalesce deep dictionary searches after 80 ms instead of 320 ms, preserve IME composition, and reject obsolete results. Immediate core and exact-entry lookups retain their existing paths.

Install required offline assets in four fetch/verify/write lanes, writing release identity only after the required cache writes finish. Pause optional article and font warming during input and gestures. Layout, styles, screen text, rendering, card controls and navigation are unchanged.

## Data and compatibility

Learner-data epoch remains 1. No persisted schema, canonical JSON format, operation identity, card ID, export, backup or FSRS parameter changes. No history is pruned. Existing version 1 data stays readable and rollback-compatible. Caches are disposable in-memory accelerators and never establish writer/session authority; changed bytes, deleted operations and changed policy invalidate reuse.

This patch retains whole-scope storage reads and whole-record integrity receipts. A worker-owned record runtime and per-entity write protocol need a separate versioned migration and recovery implementation; they are not claimed by this release.

## Verification

Coverage includes canonical bytes and SHA parity, lossy/accessor input rejection, cached-subtree size/depth limits, journal additions/removals, stale ownership/session checks, transaction abort/retry, actual SQLite crash/reopen, immutable view reuse, IME/stale-search behavior, foreground/background scheduling, and failed offline-install cleanup.

The local full test run passed its non-browser tests; browser suites could not launch because the required Playwright binaries were unavailable after a failed download. Full Chromium/WebKit and release CI remain mandatory before merge. No physical-phone speed result or production deployment is claimed. The publisher attaches the complete CI receipt and live identity after admission. The reproducible CPU diagnostic is `node scripts/benchmark-record-backend.mjs`; it is not an end-to-end latency measurement.
