# Bunki / KAIRO 1.0.0

First numbered release, established October 12, 2026 (Asia/Tokyo). This numbering
starts here; it does not invent version numbers for earlier development builds.
The published GitHub Release and its attached record establish release status.

## Changes

- Establish one product version, synchronized into the installed app and build identity.
- Show the installed version and its release notes in **Me → Settings**.
- Require increasing release numbers and completed release notes for production PRs.
- Preserve the exact deployed package, CI proof, checksums and source identity in GitHub Releases.
- Automatically check the public build identity before publishing the release record.
- Carry forward the October 12 integrated application: the redesigned rooms,
  N2/N1 and specialist decks, contextual reading, sentence mining, and review/player fixes.

## Data and compatibility

Learner data, card IDs, backup formats and FSRS parameters are unchanged by the
versioning layer. The scheduler remains FSRS-6 through ts-fsrs 5.4.1 with
`bunki-fsrs6-r090-defaults-v1`. Learner-data epoch 1 is a release compatibility
label; it is not an IndexedDB version or a migration of the existing record.

Continue using the same installed app and origin. Updates wait for existing app
windows to close. Do not clear website data or uninstall to obtain an update.
Previously fetched content is available offline; an unread article, uncached
audio, or a provider-backed AI request may still require a network connection.

The first numbered release adds no data migration and remains compatible with
the recorded October 12 unversioned baseline. Prefer a corrective patch release
over moving a tag or resetting the production branch.

## Verification

The existing full release battery remains mandatory, including Chromium/WebKit,
storage, review, backup, offline and deck checks. Versioning controls additionally
reject identity drift, non-increasing versions, incomplete notes, incompatible
unplanned migrations, mismatched proof and attempts to replace published assets.
The Settings acceptance tour checks the installed version in both languages.

The release publisher attaches the actual full CI receipt and records its
retry/flake history. A version number is not a claim of physical-iPhone testing,
native App Store delivery, or completion of every future product goal.
